## 方法与取舍

1. **修参考动作后再评估/微调真实策略（建议采用）**：修复四元数与世界坐标旋转，按足部几何计算地面，做温和的时域平滑和适度降速，然后评估既有策略，必要时训练新的独立运行。改善来源可测量，需要一定训练时间。
2. **仅在既有策略输出端增加低通/限速**：快速，但可能增加控制滞后或破坏支撑；需要独立验证后才能使用，不能代替源数据修复。
3. **仅平滑录制后的轨迹或播放参考动作**：能迅速产生好看的视频，但不能证明策略运动改善，不作为本次交付办法。

第一项符合用户已经确认的取舍。滤波强度、降速倍数与必要的训练时长由 Codex 根据测量选择，不假设用户指定了具体数值。

## 实施范围

### 动作转换和连续性

- 统一显式处理 NPZ wxyz、CSV xyzw、MuJoCo wxyz；世界 Z 旋转同时作用于根位置和姿态。
- 使用关节名称映射和机器人模型验证列顺序、有限值、四元数归一化、帧率和关节限位。
- 从 NPZ 读取真实 fps，输出固定且明确的 CSV 源帧率，并写入元数据与来源信息。
- 平滑根平移、关节轨迹和旋转；旋转采用连续四元数/旋转插值，不能直接把四元数当欧拉角滤波。
- 依据足部碰撞几何及接触阶段处理地面，不用错误姿态下的脚踝高度进行逐帧校正；保留摆腿和可能的腾空。
- 允许轻度放慢节奏；先用保守参数测量，避免把踢腿动作抹平。
- 原始和改进 CSV 分开保存，记录所有处理参数。

### 流水线和配置

- 在当前项目内提供统一入口，支持从本地视频或既有 GMR NPZ 开始，串联转换、训练、评估、导出、一致性校验和渲染。
- GVHMR/GMR 代码、权重和环境仍可保留在外部目录；通过参数定位并预检，不硬编码用户家目录。
- 上游调用与手工命令一致；支持复用已有中间产物；阶段失败立即停止并报告。
- 自定义 motion 从 run 配置恢复；允许明确指定评估 motion，保持策略结构等严格校验。
- 每次运行记录输入哈希、帧率、参数、检查点和各阶段结果，避免旧模型与新动作混用。
- 修复导出 raw action 语义，随模型提供动作缩放/默认姿态等接口元数据；一致性或非有限结果失败必须非零退出。

### 策略和演示

- 先评估 10000 轮模型对改进参考动作的完整物理 rollout。
- 如果表现不满足要求，创建新训练目录做有边界的训练/微调，保留旧运行；改变动作/奖励时不能伪装为原运行的无变化续训。
- 只有实测必要时才调整动作连续性奖励或控制平滑，并保证训练、评估、导出使用一致的动作语义。
- 输出 50 fps 的真实仿真视频，以及原版/改进版对照；逐段按真实时间对齐，标注处理后的动作节奏。
- 不对仿真后的关节轨迹做滤波后冒充策略运动，不靠丢帧或慢放掩盖问题。

## 验收

- 转换回归覆盖四元数顺序、世界旋转、足底高度、帧率、无效输入、限位与连续性。
- 统一入口至少完成一次从既有 GMR NPZ 到评估、导出、校验和视频的真实运行；上游命令预检及参数传播有测试。
- 完整优化片段无失败，记录实际终止原因和完成步数。
- 改进策略在同一物理后端/控制频率测量，目标是加速度和 jerk RMS 相对旧策略降低至少 30%，同时保持主要动作、跟踪误差和支撑稳定性；达不到则报告实测，不把视频外观当作通过。
- 原动作与新动作节奏不同的比较采用归一化相位，分别报告参考自身的平滑变化和策略跟踪误差。
- 验证 TorchScript 与 eager 的前向和闭环一致性、失败退出码，并运行现有测试。
- CPU/MuJoCo 先验收，再在 mjwarp 上复核同一检查点；不以两个后端完全同轨迹为目标。
